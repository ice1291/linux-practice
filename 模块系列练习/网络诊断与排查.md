# 网络诊断与排查

## ping：测试与目标主机的连通性
运维看点：不仅看能不能通，还要看 time（延迟）和是否有 packet loss（丢包）。如果延迟突然飙升或大量丢包，说明网络链路出了问题。

## curl：在命令行里模拟浏览器发起HTTP/HTTPS请求
运维看点：-I（大写 i）只获取响应头（Headers），不下载整个页面，非常适合快速检查服务状态码。-v 可以显示详细的握手过程，排查证书或重定向问题。

## traceroute / tracepath: 路由追踪器，显示数据包从机器到目标主机经过的所有路由节点（跳数）；traceroute/tracepath 域名/ip
运维看点：如果在某一跳之后突然超时或延迟激增，说明问题出在那个特定的路由器或网络节点上。

## tcpdump:在网卡上抓取网络数据包；tcpdump [选项] [参数]
运维看点：当所有常规命令都看不出问题时，抓包是终极手段。比如 tcpdump -i eth0 port 80 -nn 可以抓取 80 端口的流量，-nn 表示不解析主机名和端口名，直接显示 IP 和端口，速度更快
-i 指定网卡 ；port 过滤端口 ；-nn 不解析主机名和端口名 ； -c n 限制抓包数量 ；-w 文件名 把抓包结果保存到文件

## nslookup / dig : DNS翻译 ，查询域名解析记录 ; nslookup/dig  域名/ip
运维看点：当 ping 域名失败但 ping IP 成功时，第一时间用这两个命令检查 DNS 是否解析正确。
默认情况下 dig 输出信息很多，如果只想看答案部分，可以加上 +short 参数，让输出更简洁：dig www.baidu.com +short。
如果想指定某个 DNS 服务器进行查询，比如用 Google 的 8.8.8.8，可以这样写：dig @8.8.8.8 www.baidu.com

# 实战
场景 1：快速检查服务状态
运维群里有人反馈网站打不开。你怀疑是 Nginx 挂了或者返回了 502 错误。
任务：请写出一条命令，向 http://192.168.1.100 发起请求，只获取响应头，快速查看 HTTP 状态码。
curl -I http://192.168.88.131
如果服务是 HTTPS 的，记得加上 -k 参数来忽略证书验证错误：curl -kI https://...。
如果想看更详细的信息，比如请求和响应的全过程，可以用 -v 参数：curl -v http://...。


场景 2：排查 DNS 解析问题
你 ping www.baidu.com 提示 unknown host，但 ping 8.8.8.8 是正常的。
任务：请写出一条命令，查询 www.baidu.com 的 DNS 解析记录，看看能不能拿到 IP。
dig www.baidu.com

场景 3：定位网络链路故障
服务器访问某个外部 API 接口非常慢，你怀疑是中间某个网络节点出了问题。
任务：请写出一条命令，追踪到 api.example.com 的路由路径，查看每一跳的延迟。
traceroute api.example.com

场景 4：抓取异常流量
安全团队怀疑服务器正在遭受 CC 攻击，需要立刻抓包取证。
任务：请写出一条命令，在 eth0 网卡上抓取目标端口为 80 的流量，并且不解析主机名和端口名（直接显示 IP 和端口，提升性能）。

tcpdump -i eth0 port 80 -nn
参数 -i 指定网卡，port 80 过滤端口，-nn 不解析主机名和端口名
抓包时，数据量可能很大，建议加上 -c 参数限制抓包数量，比如只抓 100 个包：tcpdump -i eth0 port 80 -nn -c 100。 2. 为了后续用 Wireshark 等工具分析，通常会把抓包结果保存到文件：tcpdump -i eth0 port 80 -nn -w capture.pcap
