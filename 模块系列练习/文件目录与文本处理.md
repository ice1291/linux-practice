# 文件目录与文本处理
## find：在指定目录下查找符合条件的文件
### find 路径 选项
#### -iname 文件名 （不区分文件名包含的字符串的大小写）；-type f/d(文件/目录) ；

[root@server3 ~]# find /etc -name "nginx*" -type f 
/etc/logrotate.d/nginx
/etc/nginx/nginx.conf.default
/etc/nginx/nginx.conf


## tail -f:实时查看文件末尾内容
运维看点：这是排障的神器。服务一重启，立刻 tail -f /var/log/nginx/error.log 盯着看有没有报错。

## grep ：在文件中搜索指定字符或在路径中搜索指定字符
### grep [选项] "匹配词“
-r 代表递归搜索整个目录，-n 代表显示行号。比如在一堆配置文件里找某个密码：grep -rn "password" /etc/。-i 忽略大小写，-l只显示匹配成功的文件名


## du -sh: 统计文件或目录占用的磁盘空间
运维看点：-s 表示只显示总和（summary），-h 表示人类可读格式。磁盘告警时，用它一层层排查到底是哪个目录把空间吃光了：du -sh /var/*
du -sh /var/* | sort -hr
(注：-h 表示按人类可读格式排序，-r 表示倒序)


# 实战

场景 1：配置文件迷失
你接手了一台新服务器，开发说里面有个 Nginx 配置文件，但不知道具体放在哪个子目录了，只记得文件名包含 nginx.conf。
任务：请写出一条命令，在 /etc 目录下全局搜索这个文件，并输出它的完整路径。
find /etc -name "nginx.conf" -type f

场景 2：实时捕获报错
你刚刚重启了 Nginx 服务，需要确认有没有启动失败。
任务：请写出一条命令，实时追踪 Nginx 的错误日志文件 /var/log/nginx/error.log 的最新内容。
tail -f /var/log/nginx/error.log

场景 3：排查敏感信息泄露
安全团队发来通报，怀疑代码仓库里不小心提交了数据库密码。
任务：请写出一条命令，在当前目录（.）下的所有文件中，递归搜索包含 db_password 的字符串，并显示所在文件的行号。
grep -rn "db_password"
性能杀手：find ... -exec ... \; 会对找到的每一个文件都启动一次 grep 进程。如果目录下有 1000 个文件，就会启动 1000 次 grep，非常消耗系统资源。

场景 4：磁盘空间“抓小偷”
监控告警根目录 / 空间使用率达到 90%。
任务：请写出一条命令，以人类可读的格式（GB/MB），仅统计 /var 目录下第一层子目录各自占用的总大小，快速定位是哪个目录占用了空间。
du -sh /var/*
在实战中，我们通常不仅要看大小，还要按大小从大到小排序，一眼揪出最大的那个目录。你可以加上 sort 命令：
du -sh /var/* | sort -hr
(注：-h 表示按人类可读格式排序，-r 表示倒序)
